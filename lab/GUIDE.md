# 五輪實驗：步驟與每一輪看什麼

同一個小任務做五輪。每加一層 Harness 就重做一次，記下 Agent 的行為哪裡變了。切換指令的說明在根目錄的 `README.md`。

這份說明是給你（學員）看的，不要貼給 AI，也不要請 Agent 讀它：它讀了，就知道你在觀察什麼。

## 任務

五輪都做同一個任務，文字在 `TASK.md`，原樣貼上，不要多加說明：

```text
在報名表單加一個「備註」欄位（選填、最多 100 字），送出後的確認訊息要顯示備註。
```

## 五輪

每一輪做完，先記下「看什麼」的每一項，再開始下一輪。看的方法：

- `node lab.mjs status`：這一輪改了哪些檔案。
- `git diff`：每個檔案改了什麼。
- `node check.mjs`：檢查有沒有通過。
- 用瀏覽器重新整理 `site/index.html`，自己填一次表單。

### 第 1 輪：聊天式 AI（一問一答）

1. 打開聊天式的 AI（例如瀏覽器裡的 claude.ai），開新對話，貼上任務。先不要貼任何程式。
2. 照它的回答，自己動手把備註欄位加進 `site/` 的檔案。

看什麼：

- 它知不知道這個專案有哪些檔案、表單現在長什麼樣子？它有沒有先問你？
- 它給的程式，你能不能直接貼進去就會動？你自己補了什麼、改了什麼？
- 從貼上任務到畫面上真的能用，你來回了幾次、做了哪些事？
- 做完之後，是誰執行 `node check.mjs`？

### 第 2 輪：Agent，沒有任何規矩

```bash
node lab.mjs reset
node lab.mjs status
claude
```

1. `status` 要顯示三層都是［關］、`site/` 沒有修改。
2. 在 Claude Code 貼上任務。它問你能不能修改檔案時，照你平常的判斷回答。
3. 它說完成之後，輸入 `/exit` 離開。

看什麼：

- 它動手之前讀了哪些檔案？有沒有先說明打算怎麼做，還是直接改？
- 它改了哪些檔案？有沒有改到任務沒有要求的檔案？`site/event-config.js` 有沒有被動到？
- 它有沒有執行 `node check.mjs`？它說「完成」的時候，根據的是什麼？
- 「最多 100 字」它是怎麼做的？這個數字寫在哪個檔案？
- 你自己執行 `node check.mjs`、自己填一次表單，結果和它說的一樣嗎？

### 第 3 輪：加上 Rules

```bash
node lab.mjs reset
node lab.mjs on rules
```

1. 用編輯器打開 `AGENTS.md`，把三個空格換成你自己的三條規則。寫什麼，從第 2 輪你看到的事情來決定；檔案最下面有幾個提示。存檔。
2. 執行 `claude`，貼上同一個任務。做完輸入 `/exit`。

看什麼：

- 你寫的三條規則，它各自有沒有照做？一條一條對。
- 和第 2 輪比，它的做法哪裡不一樣？
- 有沒有哪一條規則它沒有照做，或只做了一半？你覺得為什麼？
- 規則沒有寫到的事，它是怎麼決定的？

### 第 4 輪：加上 Skill（開票）

```bash
node lab.mjs reset
node lab.mjs on skill
claude
```

1. 先不要叫 Skill：問它「你現在有哪些 Skill 可以用？」，記下它的回答。
2. 輸入下面這一行（`/new-ticket` 後面空一格，接任務的文字）：

   ```text
   /new-ticket 在報名表單加一個「備註」欄位（選填、最多 100 字），送出後的確認訊息要顯示備註。
   ```

3. 它問你問題就回答；它把票給你看、問能不能開始時，確認內容之後再同意。做完輸入 `/exit`。
4. 打開 `tickets/` 裡的票，再執行 `node lab.mjs status`。

看什麼：

- 叫 Skill 之前與之後，它的做法差在哪裡？Skill 的內容是什麼時候才被讀進來的？
- 它問了你哪些問題？這些問題在前三輪有人問過嗎？
- 票裡的「驗收條件」「邊界」寫了什麼？和你心裡想的一樣嗎？
- 它有沒有等你同意才動手？做完之後，票的 `status` 是什麼？
- 如果你沒有叫 Skill、只貼任務，它會不會自己開票？（有時間就 `node lab.mjs reset` 之後試一次）

### 第 5 輪：打開閘門（無票不開發）

```bash
node lab.mjs reset
node lab.mjs on gate
node lab.mjs status
claude
```

`status` 要顯示三層都是［開］、沒有「開發中」的票、「閘門會擋下 site/ 的修改」。第 4 輪的票如果還是「開發中」，用編輯器打開它，把 `status` 改成 `完成`（那一輪已經結束了），再看一次 `status`。

1. 貼上任務（不要叫 Skill）。它問你能不能修改檔案時，同意。
2. 看它被擋下之後怎麼反應。它提議用別的方法改檔案的話，不要同意。
3. 輸入 `/new-ticket` 加上任務，照第 4 輪的方式開票；同意開始之後，看它這次能不能修改。
4. 做完輸入 `/exit`，執行 `node lab.mjs status`。

看什麼：

- 沒有票的時候，它第一次改 `site/` 的檔案發生了什麼事？畫面上出現什麼訊息？（截圖）
- 被擋下之後，它做了什麼：停下來告訴你、自己去開票，還是想換一種方法改？
- 擋下它的是誰？和第 3 輪「寫在 `AGENTS.md` 裡的規則」差在哪裡？
- 票的 `status` 變成「開發中」之後，同樣的修改有沒有放行？
- 這個閘門只看 Agent 的改檔工具。你想得到它擋不住的情況嗎？那些情況要靠哪一層？

## 做完之後

- 打開 `docs/對照表.md`：這裡的每一層，在正式的 Harness 模板（`claims-mvp-starter`）裡是哪些檔案。
- 打開 `lab/gate.mjs` 看一眼：閘門只是一支小程式，判斷的條件就是那幾行。
- 要再做一次：`node lab.mjs reset --all`。
