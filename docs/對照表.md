# 對照表：迷你版與正式的 Harness 模板

你在這個 Repo 親手加上的每一層，在正式的 Harness 模板（`claims-mvp-starter`，Day 9 下午後半與 Day 10–12 用的練習 Repo）裡都有對應的檔案。道理一樣，只是正式的模板寫得更完整。

| 層 | 管住什麼 | 迷你版（這個 Repo） | 正式模板（`claims-mvp-starter`） | 拜託還是強制 |
|---|---|---|---|---|
| Rules（規則） | Agent 不知道這個專案的規矩，自己挑做法 | `CLAUDE.md`（一行 `@AGENTS.md`）、`AGENTS.md`（你寫的三條規則）；用 `node lab.mjs on rules` 啟用 | `AGENTS.md`（技術棧、目錄分層、核心原則、Ticket 工作流、改完一定要跑的最小驗證、嚴禁）、`CLAUDE.md`（Claude Code 專屬的補充，開頭要 Agent 先讀 `AGENTS.md`） | 拜託：Agent 每次都會讀到，但照不照做靠它自律 |
| Skills（技能） | 同一種工作每次做法不一樣、漏步驟 | `.claude/skills/new-ticket/SKILL.md`（開票）；用 `node lab.mjs on skill` 啟用，輸入 `/new-ticket` 叫它 | `.agents/skills/` 底下每個資料夾一個 Skill（`pm`、`dev`、`framework`、`team-leader`、`setup`、`run-checks`…），步驟寫在各自的 `SKILL.md`；`.claude/skills/` 是讓 Claude Code 找得到它們的入口。開票在 `pm` 這個 Skill 裡，實際建檔用 `scripts/new-ticket.sh`（`make new-ticket`） | 拜託：叫到才載入，載入後照步驟做，仍然靠自律 |
| 閘門 | Agent 沒照規矩就動手 | `.claude/settings.json` 的 PreToolUse hook 執行 `lab/gate.mjs`：沒有「開發中」的票就擋下 `site/` 的修改；用 `node lab.mjs on gate` 啟用 | `.claude/settings.json` 的 `hooks`：`scripts/ticket-gate-hook.sh`（無票不開發，守 `scripts/framework-config.sh` 的 `PRODUCT_DIRS`，也就是 `frontend/`、`backend/`）、`scripts/git-sync-gate-hook.sh`（落後遠端時擋下 `git push`）、`scripts/session-start-hook.sh`（每個新對話先注入開場簡報的規則與專案現況） | 強制：由 Claude Code 執行，Agent 沒辦法說服它 |
| 人工確認 | 不能回頭、會影響別人的動作，Agent 自己決定就做了 | 沒有做成機制：這個迷你版只靠 Claude Code 預設的詢問（它要改檔案、要執行指令時會先問你），以及開票 Skill 裡「你同意才把票改成開發中」那一步 | 這一層在正式模板是 Claude Code 的權限設定＋`AGENTS.md` 的兩道確認閘。權限設定在 `.claude/settings.json` 的 `permissions`：`allow` 列出不用問就能執行的指令（例如 `make check`、`git status`），`deny` 列出一律不准的（`Read(./.env)`），其他的動作都會先問你。兩道確認閘寫在 `AGENTS.md` 的「Ticket 工作流」與「嚴禁」：開票後先問「現在開發嗎？」，檢查綠燈後先問「上實機嗎？」，每次同意只算一次 | 權限設定是強制；兩道確認閘是拜託 |

## 票

| | 迷你版 | 正式模板 |
|---|---|---|
| 放在哪裡 | `tickets/LAB-01-短題.md` | `tickets/<你的前綴>-01-短題.md`（前綴用 `git config ticket.prefix` 設定） |
| 欄位 | `id`、`title`、`status`，加上目的、驗收條件、邊界 | 多了 `roles`、`owner`、`spec`、日期等欄位，格式見 `tickets/README.md` |
| 狀態 | 待開發 → 開發中 → 完成 | 一樣，另外有「作廢」 |
| 誰檢查格式 | 沒有 | `scripts/ticket-lint.sh`（`make ticket-lint`，包含在 `make check` 裡） |
| 閘門什麼時候放行 | 有一張 `status` 是「開發中」的票 | 有「待開發」或「開發中」的票 |

## 檢查

| | 迷你版 | 正式模板 |
|---|---|---|
| 指令 | `node check.mjs` | `make check`（票務、程式風格、型別、測試、正式版打包） |
| 通過時的最後一行 | `[check] OK` | `[check] OK` |
| 誰規定要跑 | 你在 `AGENTS.md` 寫的規則（如果你有寫） | `AGENTS.md`「改完一定要跑的最小驗證」與 `run-checks` 這個 Skill；推上 GitHub 之後 `.github/workflows/` 的 CI 會再跑一次 |
